# DevKit 1.1.0 Parallel Scheduling Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver DevKit 1.1.0 with G-drive-only, quota-free Fast Lane scheduling; disjoint parallel writers; explicit A1/A2/A3 Relay stages; bounded conflict splitting; reviewer-gated coordinator integration; a host-attested child-route contract; a host-attested new-empty-project index bootstrap that does not turn missing index into NO_SAFE_WORK; and explicit post-merge retention rounds that can only yield a host-verified branch/worktree cleanup request after no rollback.

**Architecture:** Keep the existing fail-closed host boundary: this repository compiles and validates descriptors, while the desktop host owns real session launch, worktree creation, model permission decisions, and any destructive Git/worktree cleanup. Move all account-quota material out of executable Fast Lane and host-intent paths; preserve capacity, lease, scope, evidence, and integration-proof gates. Model the three-stage workflow in Relay, with A1 as the only write-capable stage and A2/A3 as snapshot-bound read-only evidence producers. A verified new-empty-project attestation yields only an index-bootstrap descriptor, then a receipt-backed recompile to normal indexed scheduling. Persist a candidate-bound cleanup ledger whose only output is a revalidated host-operation request; absence of explicit policy or any failed recheck preserves the branch and worktree.

**Tech Stack:** Python 3.11+, uv, pytest, Ruff, Pyright, JSON policy assets, Git worktrees.

## Scheduler topology V1 implementation boundary

`2718lab-devkit/scheduler-topology-v1` binds the plan, lease, and G-drive
worktree as auditable opaque identity values. The A/B/C groups are the main
conversation (review and integrate), scheduler, and writer. Each scheduler is
limited to a `1:3` writer relationship. Design and prewarm are read-only, do
not count as writers, and remain subject to actual host slots, host capability,
lease, and safety gates. Cross-scope work requires a `declared-child` split
that strictly reduces conflict; otherwise return `UNSPLITTABLE_SCOPE_CONFLICT`.
This plan does not restore account-usage quota, D-drive temporary roots, or a
parent model ceiling, and does not weaken host capability, lease, worktree,
review, or safety gates.
