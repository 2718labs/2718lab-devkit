# BK-03 Skill and Agent Roles

Owner: terra-skill
Depends on: ORCH-04, BK-01

## Goal

Create the thin Codex coordinator Skill, progressive references, and plugin-bundled Luna/Terra/Sol agent definitions.

## Context

Read `contracts/orchestrator-api.md`, `contracts/bugkiller-policy.md` and `contracts/host-boundaries.md`. The Skill must work in `DEGRADED_SKILL_ONLY` mode when MCP or host-injected peer messaging is unavailable.

## Write Scope

- `skills/bugkiller/SKILL.md`
- `skills/bugkiller/references/`
- `agents/bugkiller-*.md`
- `agents/openai.yaml`
- `skills/bugkiller/scripts/validate_bugkiller.py`
- `mcp-tools/tests/test_bugkiller_assets.py`

## Steps

1. Write failing structure, YAML-front-matter, Markdown-body, UI-metadata and validator tests before assets.
2. Keep SKILL.md short; detailed state, routing and security live in focused references.
3. Define Luna/Terra/Sol in plugin `agents/bugkiller-*.md` using YAML front matter plus Markdown instructions, and declare required UI metadata in `agents/openai.yaml`.
4. Configure Luna/Terra read-only roles, one Terra workspace writer and Sol read-only escalation; MCP emits only authorized minimum direct-delivery instructions, while the sending agent calls host-injected `collaboration.send_message` without gaining broader card, contract or write access.

## Acceptance

Run asset tests and `validate_bugkiller.py`; agent files validate as YAML front matter plus Markdown, `agents/openai.yaml` validates as UI metadata, low-risk instructions explicitly prohibit automatic reviewer/Sol, and peer-message guidance preserves durable-mailbox recovery, TTL and permission boundaries.

## Return

Changed files, plugin-bundled agent discovery behavior, validation output and Codex-version assumptions.
