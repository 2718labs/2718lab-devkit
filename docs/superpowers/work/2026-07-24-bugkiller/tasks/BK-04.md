# BK-04 Approvals and Effects

Owner: terra-effects
Depends on: ORCH-04, BK-01

## Goal

Add canonical approval manifests and crash-recoverable commit/push/PR effect journal.

## Context

Read `contracts/host-boundaries.md` and `contracts/orchestrator-api.md`. Database grants are audit records, not proof of human identity. Peer mailbox records remain scoped to recipient and are not approval evidence.

## Write Scope

- `mcp-tools/bugkiller/approvals.py`
- `mcp-tools/bugkiller/service.py`
- `mcp-tools/tests/test_bugkiller_approvals.py`

## Steps

1. Write failing tests for missing fields, expiry, denial, single use and manifest mismatch.
2. Bind common repo/diff/test/risk fields plus action-specific commit, remote/ref or PR payload.
3. Implement `PREPARED`, `GRANTED`, `DENIED`, `CLAIMED`, success and failure states.
4. On recovery query external facts before retry; tests use fake host/provider only. Do not treat a peer message, correlation id or artifact hash as an approval or broaden its write scope.

## Acceptance

Run approval tests. Changing diff, HEAD, origin, test hash, ref or PR payload must reject the old grant; commit approval cannot authorize push/PR.

## Return

Changed files, manifest schema, effect states, test output and host limitations.
