# RT-03 Strict Claim Runtime Wiring

Owner: sol-ultra-runtime-fix
Depends on: RT-02, IDX-04C

## Goal

Make a strict-index task claim use the project index runtime instead of
failing with `INDEX_UNAVAILABLE`.

## Context

- Real stdio reproduction: strict task registration succeeds and status is
  `ready`, but `workflow_claim` returns `INDEX_UNAVAILABLE`.
- `OrchestratorService.claim_task` requires an injected index service for its
  freshness gate.
- `workflow_claim` currently opens `_orchestrator_runtime()` without that
  service.

## Write Scope

- `mcp-tools/server.py`
- `mcp-tools/tests/test_mcp_contract.py`

## Steps

1. Add a RED regression test for strict claim runtime wiring.
2. Apply the smallest runtime composition fix.
3. Run the focused contract tests, full MCP tests, and Ruff on touched files.

## Acceptance

- A strict task claim no longer returns `INDEX_UNAVAILABLE` solely because the
  MCP wrapper omitted `ProjectIndexService`.
- Legacy non-strict claims keep their current behavior.

Changed files, RED/GREEN output, conclusion, and blockers.
