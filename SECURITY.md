# Security Policy

## Supported Versions

Before the first public release, security fixes apply to the current default
branch only. After releases begin, the latest released minor line and the
current default branch are supported; older lines receive no guaranteed fixes.

## Reporting a Vulnerability

Report suspected vulnerabilities privately. Once the public GitHub repository
is available, use **Report a vulnerability** on its Security tab to open a
private GitHub Security Advisory. If private reporting is unavailable, contact
a `2718labs` organization owner privately before disclosing details.

Include the affected version or commit, component, impact, minimal reproduction,
and redacted logs. Do not include live credentials, private repository content,
chat transcripts, or unrelated personal data.

Do not open a public issue for an undisclosed vulnerability. Maintainers will
coordinate validation, remediation, release timing, and disclosure with the
reporter without promising a fixed response deadline.
